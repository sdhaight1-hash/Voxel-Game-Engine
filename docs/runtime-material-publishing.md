# Material library / runtime publishing contract — Issue #10 final gate

Material recipe `material-recipe.json` is version **1**, produced by both Tree and Asset exports. It embeds the **same authoritative** FoliageMaterials graph/opacity/function snapshots, authored vector silhouette, effective seasonal palette, base bark/leaf colors, cutout-mode declaration and bark meters-per-repeat. `recipe_id` is a deterministic versioned, non-cryptographic FNV-1a 128-bit content identity. Geometry seed and preview time are deliberately **excluded**; graph node seeds and edited embedded image bytes are included. New recipe versions must be introduced when appearance semantics change.

The runtime recipe is for a future game asset library and remains editable; consumers can load the JSON with `RuntimeMaterialRecipe::from_json`, which revalidates its graph snapshots and material identity. `FloraPrefab`, Tree and editable `VoxelAsset` all build the **same recipe** for the same authored colors/materials/shape. The recipe also lists embedded bitmap names and image fingerprints as **unverified licensing** inputs. These are a provenance review inventory, not license clearance. No third-party art is bundled or represented as CC0.

The selected season is captured separately in `appearance-snapshot.json`, version **1**, with normalized season progress, size, a content-derived snapshot ID, per-channel texture names, color-space declarations (sRGB albedo vs linear RGBA8 PBR data), dimensions and content-derived texture resource IDs. Resource keys include the RGBA bytes, dimensions, color-space and algorithm version, allowing deduplication across seeded Flora individuals and Tree/Asset roundtrips; these fingerprints are cache identities, not secure signatures.

## Static snapshot and source files

Both exports now also provide `foliage-leaves-season.png` baked from the **same base leaf RGBA** the existing GPU preview uses, at the currently selected Season preview value. The CPU follows the WGSL legacy leaf-season palette expression at pixel centers: gradient factor `1-v`, divide by `max(species_leaf_tint, 0.12)`, multiply authored per-channel seasonal gradient, clamp at 1. Alpha/silhouette and fruit-card texture pixels are taken from the existing bake. No new graph evaluator. This path does not rasterize the animated Cherry/Coffee flower shader masks.

Files `foliage-static.obj`/`foliage-static.mtl` or `asset-static.obj`/`asset-static.mtl` reference that fixed-season texture. Their companion conventional `foliage.obj`/`foliage.mtl` or `asset.obj`/`asset.mtl` keep their previous appearance and map names. The source `.json` and the runtime material recipe both retain fully editable graphs, and texture file generation uses only the existing bounded `FoliageBakeCache` + `GraphRenderCache` rather than duplicating graph evaluations.

A static renderer may differ due to texture filtering, UV tangent reconstruction, gamma handling, color-management settings, leaf per-face vertex shade, cutout coverage rules, metallic/roughness interpretation, and the previously documented OBJ bark seam approximation. Wind, dynamic spring flower overlays, studio IBL, GGX shading, leaf transmission and time-varying season uniforms are explicitly **not** baked into the static output. Thus this contract proves **deterministic per-texel authoring/palette/channel parity**, not end-to-end pixel parity with unrelated render engines.

## Cache / invalidation contract

The resident cache is bounded in process. Identical leaves and bark across independent generated seeds share the same final-color Arc cache entry; graphs reused across species and Asset conversions share previously cached normal/roughness/metallic pixels when actual authoring inputs match. A new season changes only `foliage-leaves-season.png` and the snapshot identity, not existing bark/leaf/PBR pixels; editing the palette changes the recipe/snapshot, without forcing a new base bark/leaf bake. The GPU renderer independently compares texture bytes and does not reupload unchanged maps as previously tested. No assertion is made about global GPU deduplication across all future world chunks.

**Game-library handoff:** import the recipe and source Tree/Asset/Flora JSON once, resolve texture refs by `resource_id`, maintain bounded resource stores, and apply dynamic `season_progress`, `wind_phase` and opt-in PBR controls per instance as uniforms. Do not implement chunk streaming, automatic commercial asset licensing or runtime world materials in Issue #10. For redistributable user-imported images, record a verified source URL, author, SPDX/CC rights and attribution externally before release; `unverified` is a blocker to declaring those imports rights-cleared.

## Validation gates

All 43 species compile/serialize to the publishing contract; seven representative species cover broadleaf, conifer, palm, bamboo and coffee. Oak demonstrates source Nodes Bark graph bytes = Tree baked bark = Asset baked bark, plus exact leaf/opacity and all existing PBR map bytes, equal recipe ID and equivalent snapshots through Flora/Tree/Asset. Two different generated geometry seeds keep the same shared Arc pointers and channel content identities. Altering only season changes the season map/snapshot and not other texture IDs; changing a graph, tint, vector silhouette, source bitmap or palette updates the recipe identity and relevant outputs. Invalid versions, seasons and tampered graph data are rejected. Full Rust engine/desktop/WGSL CI gates still apply.

**Out of scope / future follow-ups:** glTF export with verified MikkTSpace tangents, real HDRI, world runtime, certified render-engine screenshot parity, richer attribution source tracking UI, physically calibrated foliage scattering. Those are separate interoperability/product goals, not a reason to keep the material-authoring roadmap open indefinitely.
